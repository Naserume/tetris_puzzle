# Tetris Puzzle

브라우저에서 돌아가는 테트리스와 테트리스 퍼즐. 빌드 도구 없이 정적 파일만으로
동작합니다.

페이지는 셋입니다.

| 페이지 | 내용 |
| --- | --- |
| `index.html` | 메인 화면. 마라톤 / 레슨 / 복습 / 랜덤 퍼즐 선택과 문제 목록 |
| `play.html` | 원본 테트리스. 중력이 있고 되돌릴 수 없습니다 |
| `puzzle.html` | 퍼즐 플레이어. 중력이 없고 되돌릴 수 있습니다 |

## 실행

ES 모듈을 쓰기 때문에 `index.html` 을 직접 더블클릭하면 브라우저가 모듈 로딩을
막습니다. 로컬 서버를 하나 띄우세요.

```sh
python3 -m http.server 8765
# http://localhost:8765
```

## 조작

기본값입니다. 우측 상단 ⚙ 버튼에서 전부 바꿀 수 있습니다.

| 키 | 동작 |
| --- | --- |
| `←` `→` | 이동 |
| `↓` | 소프트 드롭 |
| `Space` | 하드 드롭 |
| `↑` / `X` | 시계 방향 회전 |
| `Z` / `Ctrl` | 반시계 방향 회전 |
| `A` | 180° 회전 |
| `C` / `Shift` | 홀드 |
| `P` / `Esc` | 일시정지 |
| `R` | 다시 시작 |

터치 기기에서는 화면 하단 버튼으로 조작합니다.

## 설정

⚙ 버튼을 누르면 설정 창이 열립니다. 창을 여는 동안 게임은 자동으로 멈춥니다.

- **조작키**: 키를 클릭한 뒤 원하는 키를 누르면 지정됩니다. 한 동작에 최대 3개까지
  묶을 수 있고, 이미 다른 동작이 쓰던 키를 지정하면 그쪽에서 자동으로 떼어옵니다.
  `×` 로 개별 해제, 취소는 아무 곳이나 클릭. Esc 를 포함해 모든 키를 지정할 수 있습니다.
- **DAS**: 좌우 키를 누른 뒤 자동 이동이 걸리기까지의 시간 (기본 133ms)
- **ARR**: 자동 이동 중 한 칸당 간격 (기본 20ms, 0 이면 벽까지 한 번에)
- **소프트 드롭**: 아래 키를 누르고 있을 때 한 칸당 간격 (기본 25ms, 0 이면 바닥까지 한 번에)

설정은 localStorage 에 저장되어 다음 접속에도 유지됩니다. 저장이 막힌 환경
(시크릿 창 등) 에서는 기본값으로 돌아갈 뿐 동작에는 지장이 없습니다.

## 구현된 규칙

가이드라인 테트리스를 따릅니다.

- SRS 회전과 월킥 (I 피스 전용 테이블 포함)
- 7-bag 랜덤: 7개마다 각 블록이 정확히 한 번씩
- 홀드 (블록당 1회), 고스트 피스, 다음 블록 5개 미리보기
- 락 딜레이 500ms, 이동/회전으로 최대 15회까지 리셋
- T-스핀 판정 (3-코너 규칙, mini / full 구분)
- 점수: 싱글 100 / 더블 300 / 트리플 500 / 테트리스 800 × 레벨,
  백투백 ×1.5, 콤보 50 × 콤보수 × 레벨, 소프트 드롭 1칸당 1점, 하드 드롭 2점
- 10줄마다 레벨 상승, 레벨에 따른 중력 가속

## 분류

레슨·복습·퍼즐이 **같은 분류 체계** 하나를 공유합니다. `js/taxonomy.js` 에
한 번 정의되고 모든 모드가 같은 뜻으로 씁니다.

```
단계 (tier)    다루는 것이 다른 구역. 난이도 순서가 아닙니다.
  1단계  조각을 넣고 줄을 지우는 법   줄 지우기 · 스핀 기초
  2단계  점수를 만드는 기술           스핀 중급 · T-스핀 · 테트리스 · 백투백
  3단계  판 전체를 끌고 가는 법       오프닝 · 다운스택

유형 (topic)   무엇에 관한 문제인가. 정확히 한 단계에 속합니다.
난이도 (level) 진짜 난이도 사다리. 유형 **안에서** 초급 → 중급 → 고급.
```

3단계가 2단계보다 어려운 것이 아닙니다. 다루는 문제가 다를 뿐입니다.
실제 난이도 비교는 같은 유형 안에서만 뜻이 있습니다 — T-스핀 고급은 T-스핀
초급보다 어렵지만, 다운스택 초급과 비교하는 것은 의미가 없습니다.

아직 내용이 없는 칸은 메뉴에 **준비 중**으로 그대로 보입니다. 빈 칸은 정보이고
(어떤 모양을 만들 작정인지 보여줍니다) 없는 칸은 아무것도 말해주지 않습니다.
`js/taxonomy.js` 의 `PLANNED` 가 그 목록입니다.

## 세 가지 모드

| 모드 | 무엇을 고르는가 | 어떻게 채점하는가 |
| --- | --- | --- |
| 레슨 | 아직 못 푼 첫 레슨부터 순서대로 | 한 수마다 즉시 |
| 복습 | 끝낸 레슨과 **같은 유형**의 퍼즐 몇 개, 성적이 나쁜 것부터 | 퍼즐과 동일 |
| 랜덤 퍼즐 | 전체 퍼즐에서 무작위 한 문제 | 끝나고 한 번에 |

복습은 따로 만든 문제가 아니라 **유형으로 고른 퍼즐**입니다.

## 레슨과 퍼즐

둘은 같은 자료 구조에서 나오고, 판정 방식만 다릅니다.

**레슨** — 조각을 놓는 즉시 판정합니다. `answers` 중 **최선만** 정답입니다.
맞으면 ✓ 와 설명, 틀리면 ✗ 와 이유를 말풍선으로 띄웁니다.

- **맞으면 거기서 멈춥니다.** 다음 조각을 내주지 않고 설명과 함께
  `다음 수 →` 버튼을 띄웁니다. 누를 때까지 판은 그대로입니다 — 왜 맞았는지
  읽을 시간을 주려는 것입니다. 버튼 대신 `Enter` 나 조작키 아무거나 눌러도
  넘어갑니다 (되돌리기·처음으로는 제 일을 합니다).
- **틀리면 1초 뒤 스스로 되돌립니다.** 되돌아가면 같은 조각이 손에 돌아오므로
  막히지 않습니다. 그래서 레슨에는 패배가 없습니다. 틀린 수는 곧바로 손을
  돌려주고, 맞은 수만 읽을 틈을 줍니다.

차선수를 두면 그 수에 적힌 설명으로 답합니다 — "그것도 T-스핀이지만 한
줄뿐입니다" 가 그냥 "틀렸습니다" 보다 많은 것을 가르칩니다.

**레슨은 한 수로 끝나지 않습니다.** 두 가지 방식으로 이어집니다.

| 이어지는 방식 | 쓰는 법 | 버튼 문구 | 예 |
| --- | --- | --- | --- |
| **판을 유지한 채 다음 수** | 한 `stage` 안에 `moves` 여러 개 | `다음 수 →` | `lesson-three-moves` (한 판에서 세 수), `lesson-b2b` |
| **새 필드를 불러오며** | `stages` 여러 개 | `다음 판 →` | `lesson-tsd` (오른쪽 통로 → 좌우가 뒤집힌 판) |

마지막 수에서는 `완료 →` 가 뜨고, 누르면 결과가 나옵니다. 힌트 버튼은 지금 둘
차례의 수를 따라갑니다 — 2번째 수 차례에는 2번 수의 힌트가 나옵니다.

**퍼즐** — 멈추지 않습니다. 두는 동안 아무 말도 하지 않습니다. 각 수를 순위표와 맞춰 점수를
매기고, 끝나면 수마다 "무엇을 뒀고 몇 점이며 최선은 무엇이었는지"를 한꺼번에
보여줍니다. 100점이 최선의 진행입니다.

```
최선 100 · 좋음 70+ · 보통 40+ · 아쉬움 1+ · 놓침 0
```

## 되돌리기

수는 전부 기록됩니다. 한 수씩 되돌리거나(`Backspace` / `U`) 처음으로
돌아갈 수 있고(`R`), 레슨에서 틀린 수는 저절로 되돌아갑니다. 되돌리기는 조각이
나올 때마다 찍어 둔 전체 스냅샷을 복원하는 방식입니다 — 줄이 지워진 뒤에는
역연산이 지저분해지기 때문입니다.

## 문제 추가하기

레슨은 `js/lessons.js`, 퍼즐은 `js/puzzle-bank.js` 에 객체 하나를 더하면
끝입니다. 보드는 아래쪽 줄만 문자열로 쓰면 위는 자동으로 채워집니다. 미리
깔린 칸은 `X` — **회색 방해줄**로 그려집니다. 일곱 색깔은 지금 플레이 중인
조각에만 씁니다.

```js
{
  id: 'lesson-tsd',
  topic: 'tspin',            // js/taxonomy.js 의 유형
  level: 'beginner',         // beginner | intermediate | advanced
  order: 1,                  // 같은 칸 안에서의 순서
  title: 'T-스핀 더블',
  brief: '무엇을 해야 하는지 한 줄',
  stages: [{
    label: '오른쪽 통로',     // 판이 바뀔 때 띄울 이름
    board: ['XXXX..XXXX', 'XXX...XXXX', 'XXXX.XXXXX'],
    queue: ['T'],
    ordered: false,          // 생략하면 순서대로
    moves: [{
      answers: [             // 점수 높은 순
        { cells: [[3,18],[4,18],[5,18],[4,19]], score: 100,
          label: 'T-스핀 더블', note: '맞았을 때 띄울 말' },
        { cells: [[4,17],[3,18],[4,18],[4,19]], score: 55,
          label: 'T-스핀 싱글', note: '아깝지만 최선은 아닌 이유' },
      ],
      defaultWrong: '순위에 없는 수를 뒀을 때 띄울 말',
      hint: '힌트 버튼을 눌렀을 때',
    }],
  }],
  outro: '문제를 끝내고 덧붙일 말',
}
```

판정은 회전 상태가 아니라 **덮은 칸의 집합**으로 합니다. S·Z·I는 회전 상태가
달라도 같은 칸을 덮을 수 있고, 같은 칸을 덮었다면 같은 수이기 때문입니다.
`ordered: false` 를 주면 한 stage 안의 여러 수를 아무 순서로나 받습니다.

진행 상황은 localStorage 에 저장되며, 메인 화면의 "진행 기록 지우기" 로
초기화할 수 있습니다.

## 구조

```
index.html               메인 화면 — 모드 선택과 유형별 목록
play.html                원본 테트리스
puzzle.html              레슨·퍼즐 플레이어
style.css                스타일
js/pieces.js             블록 모양과 SRS 킥 테이블
js/engine.js             게임 규칙 (DOM 비의존 — 원본·퍼즐·테스트가 공유)
                         옵션 세 개로 갈립니다: grid / queue / gravity,
                         그리고 autoSpawn — 끄면 조각을 잠근 뒤 다음 조각을
                         내주지 않습니다. 레슨의 "멈춤" 이 이것입니다.
js/render.js             캔버스 렌더링, ✓/✗ 표시
js/input.js              키보드 입력 (DAS / ARR)
js/settings.js           조작키·타이밍 설정과 저장
js/settings-ui.js        설정 창
js/taxonomy.js           단계·유형·난이도와 준비 중 목록
js/lessons.js            레슨 내용
js/puzzle-bank.js        퍼즐 내용 (순위가 매겨진 정답들)
js/content.js            내용 색인, 채점 기준, 모드별 문제 선택
js/puzzle-session.js     판정·되돌리기·점수 (DOM 비의존)
js/progress.js           푼 문제와 점수 기록
js/menu.js               메인 화면
js/main.js               원본 페이지
js/puzzle-main.js        레슨·퍼즐 페이지
tests/engine.test.mjs    엔진 규칙
tests/content.test.mjs   분류·문제 풀이 가능성·채점
```

`js/engine.js` 와 `js/puzzle-session.js` 는 DOM을 전혀 건드리지 않습니다.
그래서 브라우저 없이 그대로 테스트할 수 있습니다.

## 테스트

```sh
node tests/engine.test.mjs
node tests/content.test.mjs
```

엔진 쪽은 회전 항등성, 월킥, 벽 충돌, 라인 클리어, 점수와 백투백, 락 딜레이,
T-스핀 양성/음성 판정을 검사합니다.

내용 쪽은 분류가 앞뒤가 맞는지(모든 유형이 실재하는 단계에 속하는지, 준비 중인
칸이 실제로 비어 있는지)와, **순위표에 적힌 모든 수를 실제로 둘 수 있는지**를
확인합니다. 좌표를 믿지 않고, 조각이 등장 위치에서 이동·회전(월킥 포함)·낙하로
**닿을 수 있는 자리**를 전부 탐색한 뒤 그 안에 있는지 봅니다. 최선수뿐 아니라
차선수도 전부 검사합니다 — 둘 수 없는 수에 점수를 매겨 결과창에 띄우는 것은
거짓말이기 때문입니다.
